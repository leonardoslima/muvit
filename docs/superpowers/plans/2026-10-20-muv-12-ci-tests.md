# MUV-12 — Testes canônicos no CI: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Executar `pnpm test` em cada PR com PostgreSQL descartável, bootstrap automático e preservação dos demais gates.

**Architecture:** Reutilizar os exemplos `.env.test`, o bootstrap `migrate:test` e as fixtures existentes. Adicionar um service PostgreSQL ao job canônico e impedir cache das tarefas de teste no Turbo.

**Tech Stack:** GitHub Actions, Node 24, pnpm 10, Turborepo, Vitest, PostgreSQL 16 e migrations Drizzle existentes.

**Spec:** `docs/superpowers/specs/2026-10-20-muv-12-ci-tests-design.md`.

## Global Constraints

- Preservar lint, build e typecheck existentes.
- Não criar E2E, alterar contratos, introduzir dependências ou corrigir bugs funcionais revelados pela ampliação da suíte.
- Nenhum seed global deve executar antes dos testes.
- Não exportar `DATABASE_URL` global nem copiar arquivos de produção.
- Não alterar migrations históricas, schema, seeds ou lógica de produto.
- Artefatos ficam em `artifacts/muv-12/<execucao>/`; preservar pt-BR em UTF-8 literal.

## Review Focus

- Banco vazio: o primeiro `pnpm test` deve aplicar migrations e executar as suítes sem seed manual; verificação na tarefa 1.
- Reexecução: migrations devem continuar válidas e todas as tarefas `test` devem executar sem cache; verificação na tarefa 1.
- Ambiente estrito do Turbo: os dois arquivos `.env.test` devem chegar aos comandos que já os carregam; primeira execução na tarefa 1.
- Serviço indisponível ou migration inválida: o job deve falhar e bloquear build/typecheck; revisão dos códigos de saída e dependências na tarefa 1.
- Banco compartilhado ou produção: o CI só deve usar o service descartável, e a reprodução local deve apontar ambos os arquivos para o mesmo PostgreSQL exclusivo; revisão na tarefa 2.

### Task 1: Executar a suíte canônica com bootstrap existente

**Files:**
- Modify: `.github/workflows/ci.yml` — job de testes, service, preparação de ambiente e dependência do build.
- Modify: `turbo.json` — política de cache da tarefa `test`.
- Reuse: `apps/api/.env.test.example`, `packages/db/.env.test.example`, `apps/api/package.json` e `packages/db/package.json`, sem mudanças de implementação.

**Interfaces:**
- Consumes: `pnpm test` → `turbo run test`; teste API → `@muvit/db migrate:test` → Vitest; arquivos `.env.test` nos respectivos workspaces.
- Produces: job `test`, nome `Test (Turborepo)`, dependente de `check`; `build.needs: [check, test]`; `tasks.test.cache: false`.

- [x] **Step 1: Registrar o estado inicial.** Confirmar que o workflow só executa `pnpm --dir apps/mobile test`, que Turbo permite cache de `test` e que o ambiente de verificação pertence à worktree. Não executar reset ou limpeza em banco compartilhado.
- [x] **Step 2: Alterar o job de teste.** Usar service `postgres_test`, imagem `postgres:16-alpine`, `POSTGRES_USER=muvit`, `POSTGRES_PASSWORD=muvit`, `POSTGRES_DB=muvit_api_test`, porta `5433:5432`, sem volumes. Healthcheck: `pg_isready -U muvit -d muvit_api_test`, intervalo 5s, timeout 5s e 10 tentativas.
- [x] **Step 3: Preparar ambiente e comando.** Após `pnpm install --frozen-lockfile`, copiar os dois `.env.test.example` para `.env.test` com `cp` e executar literalmente `pnpm test`. Não fornecer secrets de produção, rodar seed global ou adicionar uma segunda aplicação de migrations no workflow.
- [x] **Step 4: Preservar gates e execução real.** Atualizar a referência do build para o job `test` e acrescentar `cache: false` a `turbo.json#tasks.test`; preservar os demais campos da tarefa, versões, triggers, concorrência e gates.
- [x] **Step 5: Validar configuração.** Executar `pnpm.cmd exec turbo run test --dry=json` e conferir a presença das tarefas dos workspaces; conferir `cache: false` na configuração da tarefa `test`. Revisar o YAML para garantir ausência de `continue-on-error`, secrets e referências ao antigo job. Executar `actionlint .github/workflows/ci.yml` usando o binário de verificação obtido pelo agente principal em `artifacts/`; não adicionar dependência ao projeto somente para isso.
- [x] **Step 6: Executar com banco novo exclusivo.** Usar PostgreSQL 16 pertencente a esta execução e exemplos de ambiente; se a porta local dedicada diferir de 5433, alterar somente os dois `.env.test` ignorados para o mesmo destino. Rodar `pnpm.cmd test` da raiz. Esperado: migrations aplicadas, todas as suítes existentes chamadas e exit code 0; qualquer falha deve ser registrada sem filtragem da suíte.
- [x] **Step 7: Reexecutar.** Rodar novamente `pnpm.cmd test` no mesmo ambiente. Esperado: migrations sem duplicação, suítes executadas de novo e exit code 0. Confirmar que a mensagem de cache indica bypass para testes; cache de builds de dependências pode permanecer.
